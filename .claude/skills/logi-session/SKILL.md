# logi-session — 図解思考セッション進行スキル (v0.8.0)

## 概要

logi-bot は「ドリルダウン」と「合体ロボ作戦」という図解思考技法（永田豊志）を組み合わせ、
利用者のアイデアをオンボーディング〜5ステップの質疑応答で構造化する。
**v0.8.0 以降は Mermaid 図をクライアントサイドで動的生成**（AI が Mermaid 文字列を生成しない）。
各ノードに [0]〜[8] の番号を振り、AI・UI・エクスポートで一貫して参照する。

## 2. NodeStatus — ノードの状態管理

```typescript
type NodeStatus = "unset" | "ai_draft" | "unconfirmed" | "confirmed";
```

- **unset**: 未入力（グレー破線）
- **ai_draft**: AI が提案した値（黄色）— 利用者がまだ確認していない
- **unconfirmed**: 利用者が入力したが未確認（オレンジ破線）
- **confirmed**: 利用者が確認した確定値（青）
- **current**: 現在質問中（紫太枠）— `getCurrentTargetSet()` で動的計算

`session.nodeStatuses: Record<string, NodeStatus>` に明示的な上書きのみ保存。
デフォルトは「値あり→confirmed、なし→unset」で自動解決。

AI の応答では:
- 自分が提案した値には「（AI案）」と付記し、status = `ai_draft`
- 利用者が明示確認したら「✅ 確定」として status = `confirmed`
- 「後で確認」と言われたら status = `unconfirmed`

## 3. ステートマシン設計

```
step1_core → step2_drilldown → step3_what_how → step4_verify → step5_combine → complete
```

バルクインプット時は `first_incomplete_step` へ直接遷移（ファストトラック）。

### 各ステップのボディパーツ比喩

| ステップ | 担当ノード | 目的 |
|---|---|---|
| Step 1 | [1][2][3] | 現実・理想・提案の骨格（1要素ずつ） |
| Step 2 | [4-N][5-N] | 現実の詳細・理想の詳細（ドリルダウン） |
| Step 3 | [6-N][7-N] | What と How のペア |
| Step 4 | — | 全体俯瞰・矛盾解消 |
| Step 5 | [0][8] | イントロ・クロージングで完成 |

---

## 4. ステップ別詳細と対話ルール

### Step 1: コア抽出（`step1_core`）

**対話順序**: **厳守** — [1]→[2]→[3] を1要素ずつ聞く

1. **[1] 現実**を聞く: 「今、どんな状況（現実）がありますか？」
   - 確定後: 「**[1] 現実**として「...」を記録しました。」
2. **[2] 理想**を聞く: 「理想の状態はどんなイメージですか？」
   - 確定後: 「**[2] 理想**として「...」を記録しました。」
3. **[3] 提案**を聞く: 「現実と理想のギャップを埋める提案は？」
   - 確定後: チェックポイント発動↓

**チェックポイント（[1][2][3] 揃い後）**:
```
基本関係図ができました！

[1] 現実：〇〇
[2] 理想：〇〇
[3] 提案：〇〇

この [1][2][3] の関係で意図と違う部分はありますか？
問題なければ「次のステップへ」ボタンで Step 2 へ進めます。
```

### Step 2: ドリルダウン（`step2_drilldown`）

担当ノード: [4-N]（現実の詳細）、[5-N]（理想の詳細）

1. [4-N] を聞く: 「[1] 現実の問題点・制約を2〜3つ挙げてください」
   - 「[4-1] 〇〇、[4-2] 〇〇 を左腕に追加しました。」
2. [5-N] を聞く: 「[2] 理想を達成したとき、何が実現していますか？2〜3つ」
   - 「[5-1] 〇〇、[5-2] 〇〇 を右腕に追加しました。」
3. チェックポイント: 両方揃ったら俯瞰確認メッセージ

### Step 3: What・Howの入力（`step3_what_how`）

担当ノード: [6-N]（What）、[7-N]（How）

- What と How は **ペアで**聞く（1問で両方）
- 「[6-1] What:〇〇 / [7-1] How:〇〇 を両足に追加しました。」
- **チェックポイント（What/How 揃い後）**:
  ```
  両足が揃いました！
  [6-N] What: ... / [7-N] How: ... のペアで
  実行可能なプランになっていますか？
  問題なければ「次のステップへ」で Step 4 へ。
  ```

### Step 4: 整合性チェック（`step4_verify`）

- **[1]〜[8]** の論理整合性を俯瞰して確認
- 矛盾があれば「[X] と [Y] の間に矛盾があります」と番号で指摘

### Step 5: 頭・台座（`step5_combine`）

担当ノード: [0]（イントロ）、[8]（クロージング）

1. **[0] 頭（イントロ）**を聞く: フック・導入文
2. **[8] 台座（クロージング）**を聞く: 行動促進・CTA
3. 完成時: 「合体ロボ🤖が完成しました！全9パーツ [0]〜[8] が揃いました。」

## 5. ファストトラック処理（バルクインプット）

100文字超の入力を受けたら一括抽出モード。

1. Claude API で全フィールドを抽出（`mode: "bulk_extract"`）
2. `session.parts` にマージ、抽出済みノードを `ai_draft` でマーク
3. 応答例:
   ```
   いただいた情報から、以下のパーツを仮組みしました（AI案）:

   ✅ [1] 現実: 「...」（AI案）
   ✅ [2] 理想: 「...」（AI案）
   ✅ [3] 提案: 「...」（AI案）
   ✅ [4-1][4-2] 左腕（現実の詳細）
   ⚠️ [6-N][7-N] 両足（What/How）がまだ具体的ではありません。
   ```
4. `first_incomplete_step` から対話再開

### バルク抽出の品質原則

- **抽出できた情報のみ** 返す（推測・創作しない）
- 抽出値は全て `ai_draft` として扱い、利用者確認を経て `confirmed` に昇格

## 6. ドリルダウン品質担保

回答が抽象的な場合、以下から1〜2問を選んでツッコミを入れる。

| パターン | 例文 |
|---|---|
| 数値化 | 「どのくらいですか？（件数・%・時間などで）」 |
| 具体化 | 「具体的には誰が・どこで・いつ起きていますか？」 |
| 原因追求 | 「なぜそうなっているのでしょうか？」 |
| 導入前後比較 | 「実現したら、導入前と比べて何がどう変わりますか？」 |
| 優先度 | 「複数出ていますが、最も重要なのはどれですか？」 |

## 7. クライアントサイド Mermaid 図生成

**v0.8.0 以降: AI は Mermaid 文字列を生成しない。**

図は `public/js/mermaid-builder.js` の `buildRobotDiagram(session)` がセッション状態から
自動生成する。AI はセッションの JSON フィールドを更新するだけでよい。

subgraph 構成:
```
HEAD [0] → BODY [1][2][3] → LARM [4-N] / RARM [5-N]
                             → LLEG [6-N] / RLEG [7-N] → BASE [8]
```

ノード状態は classDef で色分け:
- `unset`: グレー破線
- `ai_draft`: 黄色
- `unconfirmed`: オレンジ破線
- `confirmed`: 青
- `current`: 紫太枠（現在質問中）

## 9. AI エージェント動作指針

### ファシリテーター原則
- **誘導しすぎない**: 正解を押しつけず利用者の言葉を引き出す
- **[番号]で参照**: 応答で必ず `[1]`、`[4-2]` 等の番号を使う
- **ツッコミのバランス**: §6 の深掘りパターンを1〜2問に絞る
- **AI案の透明性**: 自分が提案した値には「（AI案）」と付記し `ai_draft` でマーク
- **バルク後の謙虚さ**: 「仮組みしました（AI案）」であって「これが正解」とは言わない

### 対話スタイル
- 一度に 1〜2 問まで
- 回答を要約して「[X] に「...」と記録しました。」と確認を取る
- ステップ名と進捗（例: `Step 2 / 5`）を常に示す
- エラー・ガード不満足時はフレンドリーに不足ノード番号を伝える
